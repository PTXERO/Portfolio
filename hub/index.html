WHERE YOUR DATA LIVES HUB v2.0

Every app on this site (SEARCH//NET, SOCIAL, ASCII//RENDER, RF) talks to one small server I call a hub. It does the fetching a browser can't do on its own, and it keeps what you choose to keep: Social posts, shared renders, SearchNet backups. You pick which hub, per device, and can change it whenever. No email, password or name needed.

THE THREE CHOICES

Shared PTXERO hub default

Works out of the box. Daily limits per person (table below). Anything you leave there is deleted after 180 days without use. Keeping data on it is optional. You can export or delete everything yourself at any time.

My own hub

A free Cloudflare Worker plus a free Supabase project that you own. No limits, you decide how long data is kept. Set it up once (steps below, about 15 minutes), then point the apps at it with one setting.

This device only

Offered where an app can work with no hub at all. Nothing leaves the device, nothing is shared or backed up.

The switch is in each app: SEARCH//NET → SOURCES → YOUR DATA · SOCIAL → ⚿ MY KEY → YOUR DATA & HUB · the RF gallery's @ID chip · ASCII//RENDER's @handle bubble (it opens Social). One choice covers all of them on that device, and your key file carries it to other devices.

YOUR PTXERO ID

You are @… on this device. A short anonymous handle: a 2-letter prefix you can change and a 4-character suffix. Behind it is a key made in this browser the first time one of the apps loaded. Every request that stores something is signed with that key, and the hub ties the key to your handle the first time it sees it. After that only a device with the key can act as you. There's nothing to guess and no password on the server to leak. Limits are counted per id, so nobody can burn through yours.

The key file is your account. Download it once (⬇ KEY FILE in any app's YOUR DATA panel, or MY KEY in Social) and import it on another device or after clearing your browser. Lose it and the handle can't be recovered. You'd just start over as a new one.

Before keys, Social proved who you were with a per-device secret. Those profiles move over the first time they post from the same device: the old secret is sent once, the key gets tied to the handle, and the secret stops mattering.

SET UP YOUR OWN HUB

Two free accounts, one paste each. No command line. About 15 minutes the first time.

1

Create a database at Supabase

Go to supabase.com → Start your project (sign in with GitHub or e-mail) → New project. Any name and region; set a database password and keep it somewhere safe (you won't need it again for this).

The free tier is plenty. Supabase pauses free projects after a week with no traffic. The hub's daily housekeeping keeps it awake.

2

Paste the database setup

In your project: left sidebar SQL Editor → New query → paste the whole file → Run. It creates every table the apps use, read-only access for pages, and the hub's own tables. It is safe to run again later.

OPEN RAW
3

Copy three values from Supabase

Project Settings (gear icon) → API:

ValueLooks likeWhere it goes
Project URLhttps://abcd1234.supabase.coWorker variable SUPABASE_URL, and the apps' "Supabase URL" box
Publishable / anon keysb_publishable_… or a long eyJ…The apps' "publishable key" box (safe in a browser, it can only read)
Secret / service_role keysb_secret_… or a long eyJ…Worker secret SERVICE_KEY. Only there, never in a page
4

Create the Worker at Cloudflare

dash.cloudflare.com → sign up (free; it asks you to pick a *.workers.dev subdomain the first time) → Workers & Pages → Create → Start with Hello World → name it (hub is fine) → Deploy.

Then Edit code, select everything in the editor (Ctrl/⌘+A), delete it, paste the hub, and press Deploy.

OPEN RAW

The Worker file contains no secrets. Your address is shown on the Worker's page: https://hub.<your-subdomain>.workers.dev.

5

Give it its settings

On the Worker's page: Settings → Variables and Secrets → Add, one at a time, then Deploy:

NameTypeValue
SERVICE_KEYSecretthe Supabase secret / service_role key from step 3
SUPABASE_URLTextyour Project URL, e.g. https://abcd1234.supabase.co
ADMIN_UIDTextyour own 4-character suffix (…). Makes you the owner: no limits, never auto-deleted, moderation rights in Social
ALLOWED_ORIGINSText, optional* to let any page use it, or a comma-separated list of sites. Default: https://ptxero.neocities.org (the hosted apps). Fetch routes answer any site regardless
LIMITSText, optionalJSON to change the limits for guests, e.g. {"fetch":1000,"writes":500,"store_bytes":104857600,"blob_bytes":1048576,"anon_fetch":100}
RETENTION_DAYSText, optionalhow long an unused identity's data is kept (default 180, minimum 7)
BUCKETText, optionalstorage bucket name; the SQL created renders
6

Turn on the daily housekeeping

Settings → Triggers → Cron Triggers → Add → 0 4 * * * (once a day). This is what erases identities nobody has used for RETENTION_DAYS, trims the usage counters, and keeps the Supabase project from pausing.

7

Test it

A good answer shows the hub version, says it stores (SERVICE_KEY is set), and signs you in as @…. "Stores nothing" means the secret isn't there yet. A 5xx usually means SUPABASE_URL is wrong or the SQL hasn't run.

8

Point the apps at it

Open SEARCH//NET → SOURCES → YOUR DATA (or Social → ⚿ MY KEY → YOUR DATA & HUB), choose My own hub, paste the Worker address, your Supabase Project URL and the publishable key, press SAVE & TEST. Every PTXERO app on this device now uses your hub. A key file exported after that carries the setting to your other devices.

Posts, renders and backups you made on the shared hub stay there (you can EXPORT MY DATA and DELETE MY DATA on it first). Hubs are separate. Social on your hub shows the people on your hub.

KEEPING, MOVING AND ERASING

⬇ KEY FILE: your identity (and your hub choice). Keep it like a password.

⬇ EXPORT MY DATA: one JSON with everything the hub holds for you. Profile, posts, likes, comments, follows, reposts, renders and backups.

✕ DELETE MY DATA ON THIS HUB: erases all of it, including uploaded images and audio, and the id itself. Your key stays on the device so you can start fresh under the same handle.

Automatic: on the shared hub, an id unused for 180 days is erased the same way by the daily housekeeping. Opening any PTXERO app with your key counts as use.

UPDATING LATER

New app features sometimes need a newer hub. The apps tell you ("your hub is older than this app"). Repeat the paste from step 4 on the same Worker and Deploy. Settings and data are untouched. The version is in /health.

Signed = headers X-PX-Uid · X-PX-Pub · X-PX-Ts · X-PX-Nonce · X-PX-Sig (ECDSA P-256 over uid\nts\nnonce\nMETHOD\npath, 5-minute window). ptxero-id.js does this for the apps. The Worker ties the first key it sees to the handle and rejects any other.
